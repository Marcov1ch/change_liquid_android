# Дизайн: полная переверстка Android-фронта ChangeLiquid

Дата: 2026-11-16
Статус: на согласовании
Охват: основные потоки (гараж, экран автомобиля, секции, быстрое добавление, статистика). Auth/профиль/публичная страница — только ретема и иконки.

## 1. Зачем

Сейчас Android-приложение — мобильная копия веба: один длинный скролл, где гараж, рабочая область и пять секций живут подряд. Выбранная машина хранится в состоянии (`useVehicleWorkspace.ts:14`), вкладки на телефоне без подписей (`VehicleWorkspacePanel.tsx:97`), кнопка добавления — в самом низу списка (`FuelRecordsList.tsx:140`), формы — центрированные модалки (`Modal.tsx:38`). Чтобы добавить заправку, нужно выбрать машину, найти вкладку, доскроллить список, попасть в модалку. Одной рукой это неудобно.

Цель переверстки: быстрое фиксирование данных одной рукой и мобильная информационная архитектура вместо десктопной.

## 2. Цели

1. Добавление заправки/траты/пробега — не более 3 осознанных тапов с главного экрана или экрана машины, без поиска вкладок и скролла до кнопки.
2. Мобильная навигация: гараж → автомобиль → секции, системная кнопка «назад» работает.
3. Собственная айдентика Android (не копия веба), светлая и тёмная темы.
4. Единая иконочная система вместо эмодзи.
5. Статистика читается на телефоне (без горизонтальной таблицы как основного вида).
6. Все действия доступны большим пальцем в нижней зоне экрана.

## 3. Не-цели

- Изменения веб-фронтенда (`../change_liquid_frontend`) и бэкенда (`../change_liquid_backend`).
- Визуальная синхронизация с вебом.
- Новые продуктовые фичи: офлайн-синхронизация, push-уведомления, GPS-маршруты на сервере, графики расхода топлива.
- Полный редизайн auth-экранов, профиля, публичной страницы — только токены, иконки, штриховка.
- Лендинги и маркетинговые экраны.

## 4. Анти-цели

- Центрированные модалки для создания записей на телефоне.
- Вкладки без подписей и другие иконочные переключатели разделов.
- Эмодзи как структурные иконки статусов и пустых состояний.
- Desktop-таблицы как основной вид данных на телефоне.
- Ховер-зависимые аффордансы.
- Жёстко зашитые светлые цвета, ломающиеся в тёмной теме.

## 5. Ограничения

### Бэкенд (не меняется)

- Логин form-encoded; access 15 мин, refresh 14 дней; роли отсутствуют, только владелец ресурса.
- Замены создаются только `POST /vehicles/{id}/replacements/bulk` (1..10), одиночного create нет.
- Датовые узлы (`insurance`, `parking_monthly`) требуют `next_change_date`; `tire_change` — датовый с поддержкой км.
- Ремонт с компонентом автосоздаёт заглушку «ВНЕСИТЕ ИЗМЕНЕНИЕ»; её нужно редактировать.
- Даты записей не могут быть в будущем; пробег не может быть меньше максимума по заменам; хронология замен по км проверяется.
- Архивированная машина: чтение разрешено, мутации 409.
- Статистики на сервере нет — агрегирует клиент.
- Валюта в `/auth/me`, в записях её нет.
- Заправки/ремонты/траты/шины отдаются целиком, без пагинации.

### Клиент

- Capacitor 8, React 19, Tailwind 3.4, react-router 7, TanStack Query 5.
- Оффлайн-приложение: без веб-шрифтов и CDN, иконки — npm-пакет.
- Safe-area: `--sat/--sab/--sal/--sar` уже есть (`index.css:7`).
- Есть 10 unit-тестов на utils/api — не ломать.
- Новые зависимости (согласованы): `@phosphor-icons/react`, `@capacitor/app`. `@capacitor/status-bar` не нужен: в Capacitor 8 `SystemBars` входит в `@capacitor/core` и уже настроен в `capacitor.config.ts:10`.

## 6. Рассмотренные подходы

- **A. Нативный M3 «Гараж → Автомобиль»** — нижняя навигация, отдельный экран машины, FAB + нижние шторки, тёмная тема. Переиспользует формы и списки, низкий риск. **Выбран.**
- **B. «Приборная панель»** — тёмная автомобильная айдентика, кольца ресурса, одометр-hero. Сильный характер, но много кастомных компонентов и проверок контраста; отложено как возможная итерация.
- **C. «Единый журнал»** — одна лента событий с фильтрами и одним FAB. Проще, но прячет планирование ТО (статусы и остаток км) и требует сводить пять списков; отклонено.

Дополнительно решено: айдентика Android своя; из подхода B берём hero-статус и быстрые действия; из C — компактную карточку машины.

## 7. Информационная архитектура

| Маршрут | Экран |
|---|---|
| `/` | Гараж (список активных/архивных машин) |
| `/vehicle/:id/:section?` | Экран машины; `section` = `replacements` (по умолчанию), `tires`, `fuel`, `repairs`, `expenses` |
| `/stats` | Статистика; `?vehicle=:id` и `?year=YYYY` |
| `/profile` | Профиль (ретема) |
| `/login`, `/register`, `/forgot-password`, `/reset-password`, `/verify-email`, `/share/:token` | Без изменений в структуре |

Выбор машины и активная секция выводятся из URL. Неизвестный `:id` → редирект на `/` с тостом. Неизвестная секция → `replacements`.

## 8. Каркас и навигация

- `AppShell`: `header` (по желанию экрана) + `main` (скролл) + `BottomNav` + `FAB`. Паддинги снизу учитывают `--sab` и высоту навбара.
- `BottomNav`, 3 назначения: **Гараж** `/`, **Статистика** `/stats`, **Профиль** `/profile`. Активный пункт — иконка + подпись + тональная «пилюля». Пока `profile_visited === false`, на пункте «Профиль» висит красная точка онбординга; в app bar гаража профильной кнопки нет.
- `FAB` (56dp, primary) справа снизу над навбаром, скрыт на `/stats` и `/profile`, при открытой шторке и для архивированной машины. Поведение: на гараже — форма нового автомобиля; на экране машины — список «Что добавить?».
- `AppBar` на внутренних экранах: назад, заголовок, действия (поделиться, overflow). На гараже — только логотип; профиль доступен из нижней навигации.
- `Menu` (overflow): Настройки, Статистика, Пробег, В архив / Восстановить / Удалить. Заменяет четыре кнопки на карточке (`VehicleList.tsx:109`). Запуск поездки — отдельной иконкой в app bar экрана машины.

## 9. Экран «Гараж»

Сверху сегмент «Активные (n) / Архив (n)». Добавление машины — FAB «+» (подпись «Добавить автомобиль»); в app bar гаража «+» нет. В пустом состоянии — та же кнопка по центру.

Карточка машины (одна строка, высота ~88dp):

```
┌──────────────────────────────────────────────┐
│ ▍ BMW 320d                              ⋮    │
│ ▍ А123ВС77 · 184 320 км                      │
│ ▍ ближайшее: Моторное масло · 1 200 км       │
└──────────────────────────────────────────────┘
```

- Слева цветной рельс 4dp по худшему статусу.
- Строка 1: марка/модель; справа overflow.
- Строка 2: номер, пробег.
- Строка 3: ближайшее ТО (компонент + остаток км или дата); статус передаётся цветом рельса и иконкой в строке.
- Тап по карточке → `/vehicle/:id`.
- Архив: рельс нейтральный, подпись «В архиве», overflow: Статистика, Восстановить, Удалить навсегда.

Пустое состояние: иконка, «Нет автомобилей», кнопка «Добавить автомобиль».

## 10. Экран «Автомобиль»

```
┌──────────────────────────────────────────────┐
│ ←  BMW 320d                    ▶  ⇪   ⋮      │
├──────────────────────────────────────────────┤
│  Требует внимания                            │
│  184 320 км                                  │
│  Моторное масло · осталось 1 200 км          │
│  [прогресс-бар 68%]                          │
├──────────────────────────────────────────────┤
│ Замены │ Шины │ Заправки │ Ремонт │ Траты    │
├──────────────────────────────────────────────┤
│  ...содержимое выбранной секции...           │
└──────────────────────────────────────────────┘
```

- Hero-статус: худший статус (иконка + подпись), текущий пробег, ближайшая по остатку замена, прогресс.
- Вкладки секций — горизонтально скроллируемые, **с подписями** и счётчиками; активная — индикатор снизу + primary. Это осознанно отличается от текущих иконочных вкладок.
- Секции переиспользуют существующие списки и логику; меняются оболочка, строки, отступы, иконки, состояния.
- App bar: назад, название, **play/stop** (запуск и остановка отслеживания пробега), «Поделиться», overflow. Иконка меняется на stop, пока трекинг активен.
- Действия секции: добавление — через FAB, который открывает `ActionSheet` «Что добавить?». Порядок фиксированный; тип активной секции подсвечен. На вкладке «Шины» в шторку добавляется строка «Шины» (создать комплект); установка/переключение комплекта остаётся в панели шин. Поделиться и статистика — в app bar; «закрыть» больше не нужен, работает «назад».
- Архивированная машина: баннер «В архиве», FAB скрыт, формы недоступны.

## 11. Быстрое добавление

Быстрое добавление записей доступно только с экрана машины: FAB → `ActionSheet` (нижняя шторка, строки высотой 56dp).

```
━━━━━
Что добавить?
[иконка]  Заправка
[иконка]  Ремонт или обслуживание
[иконка]  Замена
[иконка]  Прочие траты
[иконка]  Пробег
```

Иконки — Phosphor, не эмодзи. Подсказок под названиями нет. Порядок фиксированный, тип активной секции подсвечен; на вкладке «Шины» добавляется строка «Шины».

Поток:

1. `Sheet` с формой выбранного типа. Предзаполнение: дата = сегодня, пробег = `current_km` (для заправки/ремонта/замены/пробега), сумма пустая.
2. Сохранение — sticky-кнопка внизу шторки, над клавиатурой и safe-area. После успеха: тост, шторка закрывается, списки и машина инвалидируются, при необходимости обновляется `current_km`.

Матрица полей:

| Тип | Обязательные | Особенности |
|---|---|---|
| Заправка | дата, км, литры, сумма | `inputMode="decimal"`, дата ≤ сегодня |
| Прочие траты | название, дата, сумма | название ≤ 100 символов |
| Пробег | новый км | должен быть > текущего |
| Ремонт | дата, км, работа, детали, компоненты | компоненты — чекбоксы; после сохранения подсветить созданные заглушки «ВНЕСИТЕ ИЗМЕНЕНИЕ» |
| Замена | компонент, дата, км или `next_change_date` | по одному элементу через bulk; датовые узлы требуют дату следующей замены |
| Шины | название, сезон | только на вкладке «Шины»; создаёт комплект, установка — отдельный поток |
| Поездка | — | запускается иконкой play/stop в app bar, записей не создаёт; в шторку не входит |

Ограничения бэкенда показываем человеческим текстом из `detail`, не глушим.

## 12. Статистика

`/stats` — отдельный экран с переключателем машины (горизонтальные чипы активных машин; по умолчанию последняя выбранная) и выбором года.

- KPI-карточки 2 колонки: Замены, Шины, Ремонт, Заправки, Прочие траты, Итого.
- График 12 месяцев — существующие CSS-бары (`StatisticsPanel.tsx`), переверстанные под ширину телефона.
- Разбивка по категориям — список строк с прогресс-барами.
- Таблица — только от `sm` и выше.
- Пустое состояние: «Нет данных за год».
- Архивированные машины: в чипах только активные; выбраная архивная машина достижима по `/stats?vehicle=:id` из её overflow-меню и показывается отдельным чипом с пометкой «В архиве».

## 15. Состояния, ошибки, пустота

- Загрузка: скелетоны карточек/строк, не спиннер на весь экран.
- Ошибка запроса: блок с текстом и «Повторить».
- Пустые списки: иконка, короткое объяснение, действие.
- Ошибки валидации: поле + текст под ним; серверный `detail` — в тосте/инлайн-алерте шторки.
- 401: выход на логин (существующий механизм refresh).
- 409 (архив): баннер, действия скрыты.
- Удаление: `ConfirmDialog` с названием записи вместо `confirm()`.

## 16. Доступность

- Тап-таргеты ≥ 48×48dp (включая кнопки в строках).
- Подписи у всех переключателей и иконок-кнопок; `aria-current` в навбаре, `aria-selected` во вкладках.
- Шторка: `role="dialog"`, `aria-modal`, focus-trap, возврат фокуса на FAB, закрытие Esc/свайпом/кнопкой, блокировка скролла фона.
- Контраст текста ≥ 4.5:1 в обеих темах; статусы дублируются иконкой и текстом.
- `prefers-reduced-motion`; увеличенный системный шрифт не ломает строки (переносы, не фиксированные высоты).
- Клавиатура не перекрывает поля и sticky-кнопку шторки.

## 17. Android-специфика

- `@capacitor/status-bar`: синхронизация цвета/иконок баров с темой.
- `@capacitor/app`: back — если открыта шторка, закрыть её; иначе `history.back()`; на корне — выход.
- `styles.xml`: убрать жёсткий `windowLightStatusBar=true`, значения задаются плагином.
- `viewport-fit=cover` уже есть; `color-scheme` в `index.html` меняется на `light dark`.
- Ориентация: портрет основной, ландшафт не ломается (скролл вкладок).

## 18. Данные и состояние

- URL — источник истины для машины и секции; `useVehicleWorkspace` сокращается до запросов и инвалидаций.
- React Query ключи сохраняются: `vehicles`, `replacements`, `tire-sets`, `fuel-records`, `repairs`, `other-expenses`, `share`.
- После создания записи инвалидируем запись-список, `vehicles` и `replacements` (как сейчас в `handle*Update`).
- «Последняя машина» — `@capacitor/preferences`, используется для выбора машины по умолчанию на экране статистики.
- Быстрое добавление не создаёт дублей: блокируем кнопку на время отправки, закрываем шторку только при успехе.

## 19. Решения после проверки сборщиком

1. **Данные для карточки гаража.** `/vehicles` не содержит дат следующих замен. Для активных машин параллельно запрашиваем `/vehicles/{id}/replacements` (`useQueries`, `staleTime` 30 с); пока данные грузятся, карточка показывает `vehicle_status` и ближайший остаток из `km_remaining`. Установленный комплект шин учитываем, когда подгрузился `/vehicles/{id}/tire-sets` (кэш общий с экраном машины, повторных запросов при переходе нет). Для очень больших гаражей (больше 10 активных машин) остаётся км-вариант — деградация без блокировки экрана.
2. **Правило «ближайшего» и «худшего».** «Худший» — `vehicle_status` с бэкенда. «Ближайший» — среди последних замен по каждому узлу (`status != replaced`) и установленного комплекта шин: для км-узлов `km_remaining`, для датовых `days_remaining`; сравниваем нормированный остаток `remaining / interval` (км: `interval_km`, даты: `interval_months * 30`), просроченное впереди, при равенстве — км-узел, затем меньший абсолютный остаток. Тексты: «осталось N км» / «до DD.MM». Утилита `nearestDue.ts` покрывается тестами.
3. **Ремонт и заглушки.** Добавление всегда начинается с экрана машины. После сохранения ремонта шторка закрывается, тост «Ремонт добавлен, заполните N замен», переход на `/vehicle/:id/replacements`. Заглушки «ВНЕСИТЕ ИЗМЕНЕНИЕ» поднимаются первыми в списке с CTA «Заполнить».
4. **GPS-поездка глобальна.** `useGpsTracker` и `TrackingBar` переезжают в `AppShell`: оверлей переживает смену маршрута, системная «назад» его не закрывает, остановка — только кнопкой. Запуск и остановка — иконка play/stop в app bar экрана машины.
5. **Бары ОС.** Используем встроенный `SystemBars` из `@capacitor/core` (уже настроен в `capacitor.config.ts:10`), переключаем `style` `LIGHT/DARK` по теме. `@capacitor/status-bar` не добавляем; из `styles.xml` убираем жёсткие light-значения.
6. **`@capacitor/app`.** Добавляем: back закрывает шторку/меню, иначе `history.back()`, на корне — выход.
7. **Порядок записей в шторке.** Фиксированный; тип активной секции подсвечен. Выбор машины в шторке не нужен — добавление идёт только с экрана конкретной машины.
8. **Добавление машины.** FAB «+» на гараже и кнопка в пустом состоянии (см. §9); в app bar гаража «+» нет. Записи с гаража не добавляются.

## 20. Проверка

Команды:

- `npm run lint`
- `npm test`
- `npm run build:android`
- `npx cap sync android` (после изменения зависимостей)

Ручной чек-лист:

- 360px и 412px: гараж, машина, все секции, шторки, статистика.
- Одна рука: FAB и нижние кнопки шторки достижимы.
- Системная «назад» из машины, из вкладки, из шторки.
- Safe-area: навбар над gesture bar, sticky-кнопка над клавиатурой.
- Светлая и тёмная темы, контраст, статусные цвета, бары ОС.
- Reduced motion; увеличенный шрифт.
- Архивированная машина: баннер, FAB скрыт, мутации недоступны.
- Пустые состояния и ошибки (отключить сеть).
- Существующие тесты зелёные; новые тесты на `nearestDue` и payload-билдеры.
